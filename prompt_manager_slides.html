031. 프로젝트 개요

왜 이 프로젝트를 만들었는가

①

개발 목적

다양한 GenAI 도구를 사용하며 흩어진 프롬프트를 체계적으로 정리하고 다룰 수 있는 나만의 프롬프트 집(House)을 구축합니다.

②

학습 목표

Python의 기본 데이터 구조(List, Dictionary), 제어문(if, while), 함수 분리를 활용해 동작하는 콘솔 프로그램을 구현하고, Git을 통한 기능 단위 커밋·브랜치 관리(checkout, merge)·GitHub 버전 관리 워크플로우를 체계적으로 적용합니다.

064.1 자료구조 선택 — List vs Dictionary

List[Dict] 중첩 구조를 채택한 이유

구분리스트 (List)딕셔너리 (Dictionary)
특징순서가 있는 데이터의 연속된 집합 (인덱스 기반)키-값(Key-Value) 쌍으로 구성된 데이터 집합
장점• 순서 보장 — 목록 출력·정렬에 유용
• 인덱스(번호)로 순차 접근 용이
• append·삭제 간편		• 키(Key) 탐색 속도 O(1)
• 각 데이터의 의미(속성) 직관적 파악
• 구조 확장 자유로움
단점• 특정 값 찾으려면 전체 탐색 O(N)
• 요소의 의미를 위치(인덱스)로만 구분		• 데이터 순서 보장되지 않음
• Key 중복 허용하지 않음

전체 List 채택 이유

사용자에게 프롬프트 목록을 1번, 2번, 3번과 같은 순번(인덱스)으로 나열해 보여주고 선택하게 하는 UI 흐름에 가장 적합합니다.

개별 Dictionary 채택 이유

하나의 프롬프트가 가지는 여러 속성(title, content, category, favorite)을 Key-Value로 관리하여 prompt["title"] 형태로 가독성과 명확성을 확보했습니다.

074.2 무한 루프(while True) 제어 구조

끝나지 않는 메뉴, 끊김 없는 사용자 경험

while True 채택 이유

하나의 기능이 끝난 후 프로그램이 종료되지 않고 다시 메인 메뉴로 돌아오는 연속적인 사용자 경험을 제공하며, 잘못된 입력 시 프로그램 종료 없이 재입력을 유도합니다.

0

메인 메뉴 종료 — main()

0 입력 시 break 문을 실행해 while 루프를 탈출하고 프로그램을 정상 종료합니다.

↩

하위 메뉴 탈출 — add_prompt() 등

입력값으로 0이 들어오면 return 문을 통해 즉시 이전 메뉴로 복귀합니다.

💡 핵심: 메인은 break로 종료, 하위는 return으로 즉시 복귀 — 두 가지 종료 흐름을 명확히 분리했습니다.
084.3 데이터 영속화(Data Persistence)

파일 포맷 비교와 채택 — JSON

포맷장점단점본 프로젝트 적합성
JSON계층형·복합 구조(Dict, List)를 1:1 직렬화 가능 / bool 타입(즐겨찾기 여부) 보존 가능데이터 용량이 텍스트에 비해 약간 큼최적 (선택됨)
CSV엑셀 등 표 형태 소프트웨어와 호환성 우수내용(content) 내 줄바꿈·쉼표(,) 포함 시 파싱 오류 위험미흡
TXT가볍고 단순 텍스트 처리에 용이구조화된 데이터(Key-Value) 파싱이 까다로움미흡

📁 prompts.json

앱 시작 시 load_prompts()로 데이터를 로드하며, 추가·수정·삭제 등 변경 발생 시 save_prompts()를 통해 자동 업데이트합니다.

📝 {title}.md

특정 프롬프트를 마크다운 표준 규격(# Heading, > Blockquote)으로 변환하여 내보냅니다.

094.4 프롬프트 수정 가이드

edit_prompt() — 단계별 수정 흐름

담당 함수 / 위치

edit_prompt() · main.py

STEP 1
수정할 프롬프트 선택

목록에서 번호를 입력해 수정 대상을 지정합니다.

STEP 2
새 제목 입력

Enter만 누르면 기존 제목 유지 (Skip).

STEP 3
카테고리 재선택

카테고리 목록에서 새 번호 선택. Skip 가능.

STEP 4
새 내용 입력 → 반영

새 본문 입력 후 변경 사항이 즉시 반영됩니다.

💡 Skip 동작은 사용자 부담을 줄이면서 부분 수정을 자연스럽게 지원합니다.
105. 사용자 입력 검증 정책 (Validation Policy)

방어적 입력 처리 4종 세트

구분예외 상황프로그램 행동 규칙 (Policy)
중복 제목 이미 존재하는 제목 입력 ⚠️ 경고 메시지 출력 후 재입력 유도 (대소문자·공백 무시 비교)
빈값 처리 Enter만 입력하거나 공백(" ") 입력 ⚠️ "내용을 입력해주세요!" 안내 문구 출력 후 재입력 유도 (.strip() 적용)
범위 초과 카테고리·목록 번호 선택 시 범위 벗어남 ⚠️ "올바른 번호를 입력해주세요!" 경고 출력 후 재입력 유도
문자 입력 숫자 선택 항목에 문자·특수문자 입력 ⚠️ try-except (ValueError) 또는 .isdigit() 검사로 차단 후 재입력 유도
💡 중복 제목 거부 이유: 동일한 제목이 존재하면 단건 조회·수정·삭제 기능 실행 중 식별 충돌이 발생할 수 있으므로 고유성(Unique Key)을 보장합니다.

127. Git 버전 관리 & 병합 충돌 가이드

체계적인 버전 관리와 충돌 해결

📋 Git 버전 관리 정책

  • 기능 단위로 나눈 10개 이상의 커밋 작성
  • feature/ 브랜치를 생성하여 작업 후 main 브랜치로 merge
  • 사용한 Git 명령어: init, add, commit, push, pull, checkout, clone, merge

🛠 병합 충돌(Merge Conflict) 해결 가이드

충돌 발생 원인: 동일 파일(main.py)의 동일 코드 라인을 서로 다른 브랜치에서 각각 수정 후 병합을 시도할 때 발생

  1. git status로 충돌 파일(main.py) 확인
  2. 파일 내 <<<<<<<, =======, >>>>>>> 충돌 표시 제거 및 최신 로직으로 코드 정리
  3. git add main.py → git commit으로 병합 완료
  4. python main.py 실행 및 테스트 후 git push origin main 반영
